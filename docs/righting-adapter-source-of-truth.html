Change propagation

Where drift can—and cannot—happen

Change an alias in righting.json

Both adapters receive it on the next run. No adapter rewrite is needed.

Change classification behavior in core

ESLint picks it up directly. Oxlint may need an implementation update even if the contract shape is unchanged.

Change diagnostic wording

Only the edited adapter changes. Exact prose is not a core-owned source of truth.

🛡️

Conformance is the drift safety net

Black-box scenario families execute each adapter through its native lint entry point and require the same allowed/forbidden outcomes and stable righting/* identities. Contract-version checks and pinned native-tool versions make incompatible changes fail closed.

Plain-English verdict

Not “copied once and forgotten.” Policy data is dynamically derived every run. What is duplicated—especially in Oxlint—is the adapter-specific implementation that interprets that data and turns it into native findings. That is the real drift risk.
